## 1. Introduction

### 1.1 Purpose

This Software Requirements Specification (SRS) document describes the functional and non-functional requirements for **Cognitive Canvas**, an AI-powered multi-agent idea studio. This document is intended for developers, designers, system architects, and academic evaluators involved in the design, development, and assessment of the system.

### 1.2 Scope

**Cognitive Canvas** is a full-stack web application that enables users to generate, critique, plan, and pitch startup ideas using a collaborative multi-agent AI system on an interactive visual canvas. The system integrates five specialized AI agents, a React-based visual frontend, a Python FastAPI backend, and is deployed using Docker microservices.

**In Scope:**
- 6-mode AI idea engine (Keyword, Expand, Merge, Analyze, Score, Refine)
- Persona-aware idea generation (Student, Entrepreneur, Hackathon)
- Automatic idea critique pipeline
- Visual roadmap generation
- Task breakdown with time estimates and difficulty ratings
- Pitch deck generation and PDF export
- Workspace save/load functionality
- Real-time streaming of AI responses

**Out of Scope:**
- User authentication or account management
- Collaborative multi-user editing
- Monetization / subscription features
- Mobile native applications

### 1.3 Definitions, Acronyms, and Abbreviations

| Term | Definition |
|------|-----------|
| **AI Agent** | A specialized microservice powered by a Large Language Model (LLM) performing a specific cognitive task |
| **Canvas** | The infinite visual workspace where nodes and edges represent ideas and their relationships |
| **Node** | A card on the canvas containing text content generated by an AI agent |
| **LLM** | Large Language Model — AI model trained on large text datasets |
| **GPT-4 Turbo** | OpenAI's advanced language model accessed via OpenRouter API |
| **Persona** | User profile (Student / Entrepreneur / Hackathon) that influences AI output style and constraints |
| **Mode** | One of 6 idea-processing operations: keyword, expand, merge, analyze, score, refine |
| **Streaming** | Real-time token-by-token delivery of AI responses to the frontend |
| **Docker** | Container platform used for packaging and deploying microservices |
| **Nginx** | Web server used as API gateway to route requests to agent microservices |
| **SRS** | Software Requirements Specification |
| **API** | Application Programming Interface |
| **CORS** | Cross-Origin Resource Sharing |

## 2. Overall Description

### 2.1 Product Perspective

Cognitive Canvas is a standalone web application that interfaces with external AI provider APIs. It is designed as a **multi-agent microservices system** where each AI agent handles a specific cognitive phase of the ideation workflow. The system connects a React frontend to a Docker-containerized backend through an Nginx API gateway.

```
[User Browser]
     ↓ HTTP
[React + TypeScript Frontend — Vite Dev / Vercel]
     ↓ HTTP (streaming)
[Nginx API Gateway — Port 8080]
     ↓ Routes by endpoint path
[5 FastAPI Microservices — Brainstormer | Critic | Roadmap | Task | PitchDeck]
     ↓ HTTPS
[External AI APIs — OpenRouter (GPT-4 Turbo) | Cerebras (Llama 3.1-8B)]
```

### 2.2 Product Functions Summary

| Function | Description |
|----------|-------------|
| Idea Generation | Generate 3 persona-tailored startup ideas from a keyword |
| Idea Expansion | Branch out 3 variations from an existing idea |
| Idea Merging | Combine two ideas into a new hybrid concept |
| Market Analysis | Analyze market size, competitors, go-to-market strategy |
| Idea Scoring | Rate idea across 5 business dimensions |
| Idea Refinement | Polish a rough concept into a professional pitch |
| Auto-Critique | Automatically critique any generated idea (strengths/challenges/recommendations) |
| Roadmap Generation | Create phase-based strategic execution plan |
| Task Breakdown | Break roadmap phases into time-estimated, difficulty-rated tasks |
| Pitch Deck | Generate investor-ready 8-slide presentations with PDF export |
| Workspace Management | Save, load, rename, and delete multiple canvas sessions |

### 2.3 User Classes and Characteristics

| User Class | Description | Technical Level |
|------------|-------------|----------------|
| **Student** | College student building side projects or semester projects. Budget: $0-200. Time: 10-15 hrs/week | Low-Medium |
| **Entrepreneur** | Experienced founder or professional seeking next venture. Focus: B2B/SaaS, $100k+ ARR potential | Medium-High |
| **Hackathon Participant** | Developer/designer building in a 24-48 hour sprint. Focus: demo-readiness and wow factor | Medium-High |

### 2.4 Operating Environment

| Component | Requirement |
|-----------|-------------|
| **Client Browser** | Google Chrome 100+, Firefox 100+, Microsoft Edge 100+ |
| **Frontend Server** | Vercel (production) or Node.js 18+ with Vite (development) |
| **Backend Server** | Linux-based Docker host, 2+ CPU cores, 2GB+ RAM |
| **Docker** | Docker Engine 24+ with Docker Compose v2 |
| **Internet Connection** | Required (for external AI API calls) |
| **Screen Resolution** | Minimum 1280×720 |

### 2.5 Design and Implementation Constraints

1. All AI generation must use OpenRouter API (GPT-4 Turbo) or Cerebras API.
2. Real-time streaming must be implemented via HTTP chunked transfer (no WebSockets).
3. Frontend data persistence limited to browser localStorage (no backend database).
4. All microservices must expose RESTful HTTP endpoints on designated ports.
5. Docker containers must communicate using Docker Compose internal networking.
6. System must function without user login/authentication.

### 2.6 Assumptions and Dependencies

- Users have a modern web browser with JavaScript enabled.
- Valid `OPENROUTER_API_KEY` and `CEREBRAS_API_KEY` are provided via `.env` file.
- Docker and Docker Compose are installed on the deployment server.
- External AI API services (OpenRouter, Cerebras) are available and responsive.

## 3. System Features & Functional Requirements

### 3.1 Feature 1: Visual Canvas Interface

**Description:** An infinite, interactive canvas where AI-generated content is represented as draggable, connected nodes.

| Requirement ID | Requirement |
|---------------|-------------|
| FR-1.1 | The system shall display an infinite scrollable/zoomable canvas using React Flow |
| FR-1.2 | The system shall represent each AI output as a distinct node with icon, color, title, and content |
| FR-1.3 | The system shall draw directed arrows (edges) connecting source nodes to generated child nodes |
| FR-1.4 | The user shall be able to drag nodes to reposition them on the canvas |
| FR-1.5 | The user shall be able to zoom in/out via a slider control |
| FR-1.6 | The system shall display a context menu on right-click / left-click of a node showing relevant actions |
| FR-1.7 | The system shall show a loading spinner when an AI agent is processing |
| FR-1.8 | New nodes shall appear with a streaming animation as content is generated |

---

### 3.2 Feature 2: 6-Mode Idea Engine (Brainstormer Agent)

**Description:** The core AI engine supporting six distinct idea-processing modes.

#### 3.2.1 Mode: Keyword Generation

| Requirement ID | Requirement |
|---------------|-------------|
| FR-2.1.1 | The system shall allow the user to enter a keyword or topic string |
| FR-2.1.2 | The system shall generate exactly 3 startup ideas based on the keyword and selected persona |
| FR-2.1.3 | Each idea shall include: a short title (4-6 words), problem statement, solution, unique differentiator, and tech stack |
| FR-2.1.4 | The keyword mode shall only be accessible from the "Start Fresh" flow on the starting node |

#### 3.2.2 Mode: Expand

| Requirement ID | Requirement |
|---------------|-------------|
| FR-2.2.1 | The system shall generate 3 variations of an existing idea node |
| FR-2.2.2 | Variations shall include: different target audience, different business model, and adjacent problem space |
| FR-2.2.3 | The expand mode shall only be triggered on non-starting idea nodes |

#### 3.2.3 Mode: Merge

| Requirement ID | Requirement |
|---------------|-------------|
| FR-2.3.1 | The system shall accept two idea inputs and combine them into a novel hybrid startup concept |
| FR-2.3.2 | The user shall be prompted to enter the second idea via a text dialog |
| FR-2.3.3 | The output shall explain the synthesis logic |

#### 3.2.4 Mode: Analyze

| Requirement ID | Requirement |
|---------------|-------------|
| FR-2.4.1 | The system shall generate a market analysis including: TAM, competitors, unfair advantage, go-to-market strategy |
| FR-2.4.2 | Analysis shall be persona-specific |

#### 3.2.5 Mode: Score

| Requirement ID | Requirement |
|---------------|-------------|
| FR-2.5.1 | The system shall score the idea across 5 dimensions: Market Viability, Technical Feasibility, Team Fit, Scalability, Innovation |
| FR-2.5.2 | Each dimension shall be rated 1-10 with a justification |
| FR-2.5.3 | An overall verdict (Pursue / Improve / Drop) shall be provided |

#### 3.2.6 Mode: Refine

| Requirement ID | Requirement |
|---------------|-------------|
| FR-2.6.1 | The system shall transform a rough, unstructured idea into a polished concept |
| FR-2.6.2 | Output shall include: refined name, elevator pitch, core features, revenue model, and tech stack |

## 4. External Interface Requirements

### 4.1 User Interfaces

| UI Component | Description |
|-------------|-------------|
| Canvas Area | Full-screen node-based React Flow canvas with pan/zoom |
| Context Menu | Right-click / left-click popup with context-aware action buttons |
| Persona Modal | 3-card modal for selecting Student / Entrepreneur / Hackathon |
| Mode Modal | 5-card modal for selecting Expand / Merge / Analyze / Score / Refine |
| Start Fresh Modal | Persona selection with keyword text input prompt |
| Selection Modal | List of parsed ideas for the "Select & Expand" feature |
| Side Panel | Workspace management panel (save, load, rename canvases) |
| Loading Overlay | Full-screen spinner shown during AI generation |
| Zoom Slider | Custom bottom-center slider for canvas zoom control |
| Footer Badges | Sponsor technology attribution (GPT-4 Turbo, Cerebras AI, Docker) |

### 4.2 API Interface

| Endpoint | Method | Agent | Request Body |
|----------|--------|-------|-------------|
| `/brainstorm` | POST | Brainstormer | `{mode, persona, user_input, user_input_2?}` |
| `/criticize` | POST | Critic | `{prompt}` |
| `/roadmap` | POST | Roadmap | `{prompt}` |
| `/tasks` | POST | Task | `{prompt}` |
| `/pitchdeck` | POST | Pitch Deck | `{prompt}` |

All endpoints return **streaming plain text** responses (chunked transfer encoding).

### 4.3 External API Dependencies

| Service | Purpose | Authentication |
|---------|---------|---------------|
| OpenRouter API | Access to GPT-4 Turbo for creative AI tasks | Bearer token (OPENROUTER_API_KEY) |
| Cerebras API | Fast Llama 3.1-8B inference for task generation | Bearer token (CEREBRAS_API_KEY) |

### 4.4 Communication Interface

- Frontend ↔ Backend: HTTP REST over localhost (development) / HTTPS (production)
- Response format: Chunked streaming plain text
- Content-Type: `application/json` (requests), `text/plain` (responses)
- CORS: `allow_origins=["*"]` on all backend services

## 5. Non-Functional Requirements

### 5.1 Performance Requirements

| Requirement ID | Requirement |
|---------------|-------------|
| NFR-1.1 | First token of AI response shall appear within 3 seconds of request |
| NFR-1.2 | Task breakdown generation (Cerebras) shall complete within 5 seconds |
| NFR-1.3 | Canvas interactions (drag, zoom, pan) shall maintain 60fps |
| NFR-1.4 | Workspace save/load shall complete within 300ms |
| NFR-1.5 | Frontend initial page load shall complete within 2 seconds |

### 5.2 Reliability Requirements

| Requirement ID | Requirement |
|---------------|-------------|
| NFR-2.1 | The system shall display an error message if any AI agent fails to respond |
| NFR-2.2 | The system shall continue functioning if a non-critical agent fails (e.g., auto-critic failure shall not block idea generation) |
| NFR-2.3 | All workspace data shall persist across browser refreshes via localStorage |

### 5.3 Security Requirements

| Requirement ID | Requirement |
|---------------|-------------|
| NFR-3.1 | API keys shall never be exposed in the frontend code or browser |
| NFR-3.2 | All API keys shall be stored in environment variables on the server |
| NFR-3.3 | CORS shall be configured to allow only approved origins in production |

### 5.4 Usability Requirements

| Requirement ID | Requirement |
|---------------|-------------|
| NFR-4.1 | A first-time user shall be able to generate their first idea within 60 seconds |
| NFR-4.2 | All modal dialogs shall have a clear Cancel/Close action |
| NFR-4.3 | Context menus shall only show options relevant to the selected node type |
| NFR-4.4 | The UI shall be responsive for screen widths ≥ 1280px |
| NFR-4.5 | Color coding shall differentiate node types (purple: brainstorm, red: critic, blue: roadmap, yellow: task) |

### 5.5 Maintainability Requirements

| Requirement ID | Requirement |
|---------------|-------------|
| NFR-5.1 | Each AI agent shall be an independent Python module with its own requirements.txt |
| NFR-5.2 | The frontend shall use TypeScript with strict type annotations |
| NFR-5.3 | Each agent shall have a health check endpoint (`GET /`) returning status info |
| NFR-5.4 | New agents shall be addable by creating a new folder, Dockerfile, and registering in docker-compose.yml |

## 6. System Constraints

| Constraint | Description |
|-----------|-------------|
| **API Rate Limits** | System depends on OpenRouter and Cerebras API rate limits; heavy usage may result in throttling |
| **Stateless Backend** | No database; all state is managed client-side in React state and localStorage |
| **Browser Storage** | localStorage limited to ~5MB; very large canvases may exceed storage limits |
| **Internet Dependency** | System non-functional without internet access (all AI API calls are external) |
| **Single-User Session** | No real-time collaboration; one user per browser session |
| **Docker Required** | Full multi-agent deployment requires Docker Engine; agents cannot run as a monolith without Docker |
| **Model Availability** | System performance depends on external model availability (GPT-4 Turbo, Llama 3.1-8B) |
